## 1. نظرة عامة على المشروع

يهدف **نظام Smart Stadium** إلى محاكاة منصة رقمية ذكية داخل الملعب لتحسين تجربة المشجعين وإدارة البيئة (مثل التبريد المرتبط بالمقاعد) ومراقبة الحساسات والتنبيهات والتوجيه داخل الملعب. المشروع مبني لتطبيق أكاديمي باستخدام **Flask** و**SQLite** وواجهة **HTML/CSS/JavaScript** فقط، دون أطر عمل JavaScript خارجية.

<a id="المتطلبات"></a>

## 2. المتطلبات التقنية

- **Python 3.10.6** (يُفضّل مطابقة الإصدار لتقليل اختلاف السلوك بين الأجهزة).
- **Flask** و**Werkzeug** (لتشفير كلمات المرور) كما في `requirements.txt`.
- متصفح حديث يدعم **Canvas API** لعرض الخرائط والرسوم.

<a id="التثبيت"></a>

## 3. تثبيت المشروع وتشغيله

### الخطوات:

1. تأكد من تثبيت Python 3.10.6

   ```
   python --version
   # يجب أن تظهر: Python 3.10.6
   ```

2. افتح موجه الأوامر في مجلد المشروع:

   ```
   cd "D:\VSCode\Projects\Smart Stadium"
   ```

3. أنشئ بيئة افتراضية:

   ```
   python -m venv venv
   ```

4. فعّلها:

   ```
   venv\Scripts\activate
   ```

5. ثبّت المكتبات:

   ```
   pip install -r requirements.txt
   ```

6. أنشئ قاعدة البيانات:

   ```
   python init_db.py
   ```

7. شغّل التطبيق:

   ```
   python app.py
   ```

8. افتح المتصفح على:

   ```
   http://127.0.0.1:5000
   ```

> **ملاحظة:** يجب أن يبقى ملف الشعار في `assets/images/Logo.jpeg` وأن تبقى خطوط **IBM Plex Sans Arabic** داخل `assets/fonts/` كما هو مطلوب للتصميم.

<a id="هيكل-الملفات"></a>

## 4. هيكل الملفات

- **`app.py`**: إنشاء تطبيق Flask، تسجيل المسارات والـ Blueprints، وتقديم مجلد `assets` عبر المسار `/assets/...`.
- **`config.py`**: المسارات العامة و`SECRET_KEY` ومسار قاعدة البيانات.
- **`database.py`**: إنشاء الجداول، دوال مساعدة، ومحاكاة قراءات الحساسات.
- **`init_db.py`**: إدخال بيانات أولية (مستخدمون، مقاعد، حساسات، تنبيهات، مشجعون، عيّنة من سجل الحرارة).
- **`routes/`**: منطق الصفحات لكل وحدة (مصادقة، لوحات، مشجعون، مقاعد، حساسات، تبريد، تنبيهات، إحصاءات، مستخدمون).
- **`templates/`**: قوالب Jinja2 لجميع الصفحات مع `base.html` الموحّد.
- **`static/css` و `static/js`**: تنسيقات منفصلة حسب الصفحة، وتفاعل Canvas و`fetch`.
- **`data/stadium.db`**: قاعدة SQLite تُنشأ بعد تشغيل `init_db.py`.

<a id="قاعدة-البيانات"></a>

## 5. قاعدة البيانات

تتضمن الجداول: `users`, `seats`, `sensors`, `fans`, `sensor_readings`, `cooling_logs`, `alerts`, `navigation_logs` مع القيود (CHECK) والمفاتيح الأجنبية الموضحة في مواصفات المشروع. التشفير لكلمات المرور يتم عبر `werkzeug.security`.

<a id="الصفحات"></a>

## 6. صفحات النظام

- **تسجيل الدخول**: واجهة RTL مع الشعار وحقول الاعتماد.
- **لوحة الإدارة**: بطاقات ملخصة وجدول آخر التنبيهات وروابط سريعة.
- **لوحة الموظف**: ملخص مختصر يركز على الحساسات والتبريد والتنبيهات.
- **لوحة المشجع**: بطاقة التذكرة والمقعد، تبريد سريع عبر واجهة برمجية، حرارة المنطقة، تنبيهات مختصرة.
- **إدارة المشجعين**: جدول، بحث في الواجهة، إضافة/تفاصيل/حذف.
- **قائمة المقاعد وخريطة Canvas**: تقسيم قطاعات الملعب وجدول تفصيلي مع فلاتر.
- **مراقبة الحساسات**: بطاقات لحظية تُحدَّث كل 5 ثوانٍ، وخريطة حرارية مبسطة.
- **التبريد**: أزرار جماعية وجدول تفصيلي بأزرار صغيرة لكل مقعد.
- **التوجيه**: حساب مسار مبسط أكاديمياً مع رسم على Canvas.
- **التنبيهات**: فلاتر أولوية وحالة، وإمكانية إنشاء تنبيه للمشرف عبر نافذة منبثقة.
- **الإحصاءات**: أرقام ملخصة، رسم بياني خطي عبر Canvas، وجدول الجنسيات.

<a id="api"></a>

## 7. نقاط نهاية API

- `POST /auth/login` — تسجيل الدخول (نموذج HTML).
- `GET /auth/logout` — تسجيل الخروج.
- `GET /api/sensors/live` — JSON للحساسات (للتحديث الدوري).
- `POST /api/sensors/simulate` — محاكاة قراءات جديدة.
- `POST /api/cooling/set` — جسم JSON: `{ "seat_id": number, "level": "off|low|medium|high|auto" }`.
- `POST /api/cooling/set-all` — جسم JSON: `{ "level": "..." }` (للموظف/المشرف).
- `GET /api/navigation/path` — معلمات الاستعلام: `gate`, `block`, `row`, `seat`.
- `PUT /api/alerts/<id>/resolve` — تحديد تنبيه كمحلول (موظف/مشرف).

<a id="التقنيات"></a>

## 8. شرح التقنيات المستخدمة

- **Flask (إطار عمل ويب)**: تخيّل مطعماً: المطبخ يحضّر الطعام، والنادل (Flask) ينقل الطلبات بين الزبون (المتصفح) والمطبخ (المنطق وقاعدة البيانات). المسارات (Routes) هي قوائم الطلبات التي يرسلها الزبون.
- **SQLite (قاعدة بيانات)**: مثل دفتر هاتف منظم بأعمدة: كل صف هو سجل، والاستعلامات تبحث أو تضيف أو تعدّل الصفوف بسرعة دون خادم قاعدة بيانات منفصل.
- **HTML / CSS / JavaScript**: HTML يشبه هيكل المنزل (الغرف والعناوين)، CSS يشبه الديكور والألوان، وJavaScript يشبه الكهرباء والمفاتيح التي تضيء أو تتحرك عند التفاعل.
- **IoT (إنترنت الأشياء)**: مثل ميزان حرارة ذكي يرسل درجة الحرارة لهاتفك؛ هنا نحاكي الحساسات بقراءات تُحدَّث في قاعدة البيانات.
- **Bluetooth Low Energy (BLE)**: مثل سماعات لاسلكية تستهلك طاقة قليلة وتتصل بالهاتف عبر موجات قريبة؛ المشروع لا يشغّل BLE فعلياً، لكنه يمثّل فكرة الاتصال المحلي بين الأجهزة والملعب.
- **واجهة API**: مثل قائمة طعام ثابتة يختار منها النظام وجبات جاهزة (JSON) دون إعادة تحميل الصفحة بالكامل.

<a id="الكود"></a>

## 9. شرح الكود المفصل

### `config.py`

- **الغرض**: تجميع الإعدادات العامة في مكان واحد.
- **دوال**: لا يحتوي على دوال؛ ثوابت فقط مثل `BASE_DIR` و`SECRET_KEY` و`DATABASE_PATH`.
- **التفاعل**: يستورده `app.py` و`database.py` و`init_db.py`.

مثال (مختصر) وشرح الفكرة:

```python
BASE_DIR = os.path.dirname(os.path.abspath(__file__))
```

- السطر يحدد مجلد المشروع لبناء مسار ملف قاعدة البيانات بشكل صحيح على أي جهاز.

### `database.py`

- **الغرض**: تهيئة اتصال SQLite، إنشاء الجداول، ومحاكاة قراءات الحساسات.
- **دوال رئيسية**: `get_connection`, `init_schema`, `simulate_sensor_readings`, `count_rows`, `fan_for_user`, `seat_by_id`, `log_cooling_change`.
- **التفاعل**: يستدعيه `init_db.py` ومسارات Flask عند الحاجة.

فكرة `simulate_sensor_readings`: تجلب الحساسات النشطة، تولّد درجة حرارة ورطوبة عشوائيتين ضمن نطاق منطقي، ثم تحدّث جدول `sensors` وتُدرج صفاً في `sensor_readings`.

### `init_db.py`

- **الغرض**: إنشاء الملف `data/stadium.db` وملء بيانات تجريبية متسقة مع مواصفات المشروع.
- **دوال**: `seed_users`, `seed_seats`, `seed_sensors`, `seed_alerts`, `seed_sample_readings`, `seed_fans`, و`main`.
- **التفاعل**: يعتمد على `database.init_schema` ويُشغَّل مرة عند الإعداد.

### `app.py`

- **الغرض**: نقطة تشغيل الخادم، تسجيل الـ Blueprints، وتقديم الملفات الثابتة تحت `/assets/`.
- **دوال**: `login_required`, `admin_required`, `assets`, `home`.
- **التفاعل**: يربط كل المسارات الفرعية من مجلد `routes`.

### ملفات `routes/*.py`

كل ملف يعرّف `Blueprint` لوحدة وظيفية:

- **`auth.py`**: التحقق من الاعتمادات وإنشاء الجلسة (`session`) وتخزين `fan_id` عند المشجع.
- **`dashboard.py`**: توجيه المستخدم حسب الدور وجمع أرقام اللوحات.
- **`fans.py`**: إدارة المشجعين مع قيود صلاحيات المشرف.
- **`seats.py`**: قائمة المقاعد وJSON للخريطة.
- **`sensors.py`**: صفحات المراقبة والسجل، وواجهات `/api/sensors/...`.
- **`cooling.py`**: يتضمن `auto_adjust_cooling` كمنطق أكاديمي مرتبط بعتبة حرارة، وواجهات التبريد.
- **`navigation.py`**: دالة `calculate_path` المبسطة ومسار JSON.
- **`alerts.py`**: عرض التنبيهات وإضافة تنبيه للمشرف، وتسوية عبر `PUT`.
- **`reports_view.py`**: تجميع أرقام وإحصاءات لصفحة الإحصاءات.
- **`admin.py`**: إدارة المستخدمين للمشرف فقط.
